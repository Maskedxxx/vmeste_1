# ВМЕСТЕ

## Что это?

**ВМЕСТЕ** — AI-платформа для персонализированного взаимодействия пользователей
с контентом психолога Бачинской.

Проект состоит из двух ключевых частей:

1. **Контент** — база знаний с материалами Бачинской (статьи, рекомендации, методики)

2. **AI-ядро** — интеллектуальная система, которая понимает запросы пользователя,
   ищет релевантный контент и формирует персональные рекомендации

Взаимодействие происходит через Telegram-бота.

## Локальный запуск (разработка)

### Требования

- Docker и Docker Compose
- Git
- OpenAI API ключ
- Telegram Bot Token (получить у @BotFather)

### Шаг 1: Клонирование

```bash
git clone https://github.com/Maskedxxx/vmeste_1.git
cd vmeste_1
```

### Шаг 2: Настройка окружения

```bash
cp .env.example .env
```

Открыть `.env` и заполнить обязательные переменные:

```env
OPENAI_API_KEY=sk-xxx
TELEGRAM_BOT_TOKEN=123:ABC
```

Переменные для PostgreSQL можно не заполнять — если они пустые,
будут использованы дефолтные значения из `docker-compose.yml`:

```
POSTGRES_DB       → vmeste
POSTGRES_USER     → vmeste
POSTGRES_PASSWORD → vmeste_password
```

### Шаг 3: Запуск

```bash
docker-compose up --build
```

### Что инициализируется автоматически

При первом запуске `docker-compose up` происходит:

```
+------------------+------------------------------------------------+
| Сервис           | Что инициализируется                           |
+------------------+------------------------------------------------+
| PostgreSQL       | - Создаётся БД vmeste                          |
|                  | - init.sql создаёт 11 таблиц                   |
|                  | - Создаётся тестовый пользователь              |
+------------------+------------------------------------------------+
| ChromaDB         | - Запускается пустой                           |
|                  | - Данные сохраняются в volume между запусками  |
+------------------+------------------------------------------------+
| API              | - entrypoint.sh проверяет наличие таблиц       |
|                  | - Запускает Telegram-бота (polling)            |
|                  | - Запускает FastAPI сервер                     |
+------------------+------------------------------------------------+
```

Таблицы PostgreSQL (создаются автоматически):
- `users` — пользователи платформы
- `sessions` — сессии общения
- `chat_history` — история сообщений
- `user_memory` — долговременная память пользователя
- `psychologist_content` — каталог материалов психолога
- `sources`, `documents`, `content_chunks` — контент для RAG
- `style_examples` — эталоны стиля общения
- и другие служебные таблицы

### Порты по умолчанию

```
+-------------+------------------+------------+
| Сервис      | Адрес            | Порт       |
+-------------+------------------+------------+
| API         | localhost:8000   | 8000       |
| ChromaDB    | localhost:8001   | 8001       |
| PostgreSQL  | localhost:5433   | 5433       |
+-------------+------------------+------------+
```

PostgreSQL использует порт 5433 (не стандартный 5432),
чтобы избежать конфликта с локально установленной БД.

### Возможные конфликты и решения

**Конфликт портов**

Если порты уже заняты, переопределите их в `.env`:

```env
API_EXTERNAL_PORT=8080
CHROMA_EXTERNAL_PORT=8002
POSTGRES_EXTERNAL_PORT=5434
```

**Конфликт контейнеров**

Если контейнеры с такими именами уже существуют:

```bash
docker rm -f vmeste-api vmeste-postgres vmeste-chroma
```

**Очистка данных**

Для полного сброса (удаление volumes с данными):

```bash
docker-compose down -v
```

**Что происходит:**

1. Пользователь отправляет `/start`
2. Бот просит ввести email
3. Пользователь вводит email
4. Бот вызывает API `POST /entry` с email
5. API проверяет email в таблице `users`:
   - Если email новый — создаёт запись в БД
   - Если email есть — загружает существующий профиль
6. API возвращает: `user_id`, `is_new`, `quiz_completed`
7. Бот показывает главное меню с кнопками

**Главное меню после авторизации:**

```

+-------------------------------------+
```

**Что происходит:**

1. Пользователь нажимает «Диагностика»
2. Запускается `diagnostic_workflow` — **параллельно** два процесса:

   **А) diagnostic_agent:**
   - Загружает профиль из `users.profile_json`
   - Вызывает LLM **последовательно** для 3 блоков (body → mind → sex)
   - Каждый блок: анализ + теги + рекомендации врачей/анализов

   **Б) recommendation_agent:**
   - Загружает профиль из `users.profile_json`
   - Загружает 6 последних записей из `psychologist_content` (ORDER BY updated_at DESC)
   - Для каждого блока вызывает LLM **последовательно**:
     - LLM получает: профиль + 6 кандидатов + подсказку блока (BLOCK_FOCUS_HINTS)
     - LLM сам выбирает лучший контент из 6 кандидатов
     - Выбранный контент исключается из списка для следующего блока

3. Результаты сохраняются в `user_memory.memory_data`

4. Бот показывает 3 блока последовательно:
   - Анализ (3-4 предложения)
   - Рекомендуемые врачи/специалисты
   - Рекомендуемые анализы
   - Теги для выбора (5-6 штук)
   - Карточка контента психолога

5. Пользователь выбирает актуальные теги в каждом блоке
6. Выбранные теги используются для **Плана на 7 дней**

> 2. Семантический поиск через ChromaDB

После диагностики становится доступен **План на 7 дней**.

```
|       |                         |                   +---+---+           |
|       |                         |                       v               |
|       |                         |              +--------------+         |
|       |                         |              |  PostgreSQL  |         |
|       |                         |              |  user_memory |         |
|       |                         |              | .memory_data |         |
|       |                         |              +--------------+         |
|       |                         |                       |               |
|       |                         |<----------------------|               |
|       |                         |                                       |
|       |<--- План на 7 дней -----|                                       |
|       |     День 1: ...         |                                       |
|       |     День 2: ...         |                                       |
|       |     ...                 |                                       |
|       |     День 7: ...         |                                       |
|                                                                         |

```

**Что происходит:**

1. Пользователь нажимает «План на 7 дней»
2. Бот передаёт теги, выбранные пользователем в диагностике
3. Запускается `week_plan_agent`:

   **Загрузка контекста:**
   - Профиль из `users.profile_json`
   - Ответы квиза из `user_memory.memory_data`
   - Результаты диагностики из `user_memory.memory_data`

   **Сбор тегов (приоритет):**
   1. Теги, выбранные пользователем в диагностике
   2. Если пусто → все теги из диагностики (body + mind + sex)
   3. Если пусто → теги из профиля (recommended_focus)

   **Кэширование:**
   - Вычисляется hash контекста (профиль + квиз + диагностика + теги)
   - Если hash совпадает с сохранённым → возвращается кэш
   - Иначе → генерируется новый план через LLM

4. LLM получает: профиль + квиз + диагностику + теги (как focus_tags)
5. LLM генерирует план **без учёта контента из базы**
6. Результат сохраняется в `user_memory.memory_data`

**Структура каждого дня:**
- `title` — название дня
- `goal` — цель на день
- `instructions` — конкретные шаги
- `tags` — связанные теги
- `focus_area` — область фокуса (body/mind/sex)

```
|       |     Тело" --------------|                         |             |
|       |                         |                         |             |
|       |   "Мой вопрос..."       |                         |             |
|       | ----------------------->|                         |             |
|       |                         |                         |             |
|       |                         | POST /chat              |             |
|       |                         | {user_id, message,      |             |
|       |                         |  topic: "body"}         |             |
|       |                         | ----------------------->|             |
|       |                         |                         v             |
|       |                         |              +-------------------+    |
|       |                         |              |  rag_chat_agent   |    |
|       |                         |              +-------------------+    |
|       |                         |                       |               |
|       |                         |         +-------------+-------------+ |
|       |                         |         v             v             v |
|       |                         |  +-----------+ +-------------+ +-------------+
|       |                         |  | users.    | | user_memory | | chat_       |
|       |                         |  | profile_  | | dialog_     | | history     |
|       |                         |  | json      | | summary     | | (последние) |
|       |                         |  +-----------+ +-------------+ +-------------+
|       |                         |         |             |             | |
|       |                         |         +-------------+-------------+ |
|       |                         |                       v               |
|       |                         |              +-------------------+    |
|       |                         |              |  Поиск в ChromaDB |    |
|       |                         |              |  collection:      |    |
|       |                         |              |  "content_all"    |    |
|       |                         |              |  WHERE topic=body |    |
|       |                         |              |  LIMIT 3          |    |
|       |                         |              +-------------------+    |
|       |                         |                       |               |
|       |                         |                       v               |
|       |                         |              +-------------------+    |
|       |                         |              |      OpenAI       |    |
|       |                         |              |      (LLM)        |    |
|       |                         |              +-------------------+    |
|       |                         |              Получает:               |
|       |                         |              - профиль               |
|       |                         |              - историю диалога       |
|       |                         |              - 3 чанка контента      |
|       |                         |              - вопрос пользователя   |
|       |                         |                       |               |
|       |                         |                       v               |
|       |                         |              +--------------+         |
|       |                         |              |  PostgreSQL  |         |
|       |                         |              | chat_history |         |
|       |                         |              +--------------+         |
|       |                         |                       |               |
|       |                         |<----------------------|               |
|       |                         |                                       |
|       |<--- Ответ AI -----------|                                       |
|       |     + ссылки на контент |                                       |
|       |     + follow-up вопрос  |                                       |
|       |                         |                                       |
|       |   [Выйти из чата]       |                                       |
|       | ----------------------->|                                       |
|       |                         |                                       |
|       |<--- Главное меню -------|                                       |
|                                                                         |
+-------------------------------------------------------------------------+
```

**Что происходит:**

1. Пользователь выбирает тему чата: Тело / Психика / Секс
2. Бот переходит в режим чата по выбранной теме
3. Пользователь задаёт вопрос
4. Запускается `rag_chat_agent`:

   **Загрузка контекста:**
   - Профиль из `users.profile_json`
   - Саммари диалога из `user_memory.memory_data` (если есть)
   - Последние 4 сообщения из `chat_history`

   **RAG-поиск в ChromaDB:**
   - Коллекция: `content_all`
   - Фильтр: `WHERE topic = выбранная_тема` (body/mind/sex)
   - Лимит: 3 чанка
   - Поиск по семантической близости к вопросу пользователя

5. LLM получает: профиль + историю + 3 релевантных чанка + вопрос
6. LLM формирует ответ на основе контента психолога
7. Ответ сохраняется в `chat_history`

**Структура ответа:**
- `message` — текст ответа
- `references` — ссылки на использованные материалы
- `follow_up_question` — предложение следующего вопроса

**Важно:** Только чат использует ChromaDB для семантического поиска контента!

## Загрузка контента психолога

Перед использованием чата нужно загрузить контент в базу данных.

### Шаг 1: Подготовка JSON файла

Создать файл `data/content.json`:

```json
{
  "source": {
    "source_type": "manual",
    "title": "Ручной ввод"
  },
  "content": [
    {
      "slug": "stress_breathing_01",
      "title": "Дыхательные техники при стрессе",
      "topic": "body",
      "content_type": "lesson",
      "tags": ["стресс", "дыхание", "релаксация"],
      "summary": "Краткое описание для каталога",
      "description": "Подробное описание урока",
      "full_text": "Полный текст материала, который будет разбит на чанки..."
    }
  ]
}
```

**Обязательные поля:**

| Поле | Описание |
|------|----------|
| `slug` | Уникальный идентификатор (латиница, без пробелов) |
| `title` | Название материала |
| `topic` | Тема: `body`, `mind` или `sex` |
| `content_type` | Тип: `lesson`, `article`, `exercise`, `meditation` |
| `full_text` | Полный текст для RAG-поиска |

**Опциональные поля:**

| Поле | Описание | По умолчанию |
|------|----------|--------------|
| `source` | Провайдер данных | `manual` |
| `tags` | Теги для фильтрации | `[]` |
| `summary` | Краткое описание | `null` |
| `description` | Полное описание | `null` |
| `price` | Цена материала | `0` |
| `url` | Ссылка на материал | `null` |

### Шаг 2: Запуск пайплайна

```bash
# Проверка данных (без записи в БД)
docker-compose exec api python scripts/content_pipeline.py --file data/content.json --dry-run

# Загрузка в БД
docker-compose exec api python scripts/content_pipeline.py --file data/content.json

# С подробным выводом
docker-compose exec api python scripts/content_pipeline.py --file data/content.json --verbose
```

### Что происходит при загрузке

```
JSON файл
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  1. ПРОВАЙДЕР                                                   │
│     source.source_type → таблица sources                        │
│     (если провайдер уже есть — используется существующий)       │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  2. ДОКУМЕНТ                                                    │
│     slug, title, full_text → таблица documents                  │
│     (дубликаты по slug пропускаются)                            │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  3. КАТАЛОГ                                                     │
│     title, topic, tags, price → таблица psychologist_content    │
│     (метаданные для отображения в боте)                         │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  4. ЧАНКИ                                                       │
│     full_text → разбиение на части → таблица content_chunks     │
│     (семантическое разбиение ~500 символов)                     │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  5. ЭМБЕДДИНГИ                                                  │
│     чанки → OpenAI API → ChromaDB (content_all)                 │
│     (векторные представления для семантического поиска)         │
└─────────────────────────────────────────────────────────────────┘
```

### Результат загрузки

После успешной загрузки данные распределяются по таблицам:

```
+------------------------+------------------------------------------+
| Таблица                | Что хранит                               |
+------------------------+------------------------------------------+
| sources                | Провайдеры (откуда пришёл контент)       |
| documents              | Исходные тексты материалов               |
| psychologist_content   | Каталог для отображения в боте           |
| content_chunks         | Разбитые на части тексты                 |
| chunk_embeddings_meta  | Метаданные эмбеддингов                   |
+------------------------+------------------------------------------+
| ChromaDB: content_all  | Векторные эмбеддинги для RAG-поиска      |
+------------------------+------------------------------------------+
```
